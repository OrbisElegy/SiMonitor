# 通知意图到声音执行接口

`AlarmNotificationSoundRouter` 消费[通知决策](alarm-notification-policy.md)，产生短警报单组或长警报持续请求，并与未注册提示的持续声音仲裁；`MonitorAlarmSequencer` 执行请求并提供有界排程记录。桌面 `SoundSettingsPanel.UseNotificationPlayback(journals)` 接通此通道，传入 null 恢复原持续模式。桌面“报警 → 通知策略”的默认方式与独立短／长覆盖调用此入口；产品默认仍为原持续播放，默认方式和条件覆盖通过版本 9 偏好保存。声音输出开关不随偏好恢复。

## 请求与单组排程

`MonitorAlarmSoundRequest.NotificationSequence` 为 0 时保留原持续播放语义。正值表示该播放 owner 中单调递增的一次声音组身份。请求仍携带 Level、VolumePercent、Timing，通过 `Validate()` 原子检查等级、音量及原声音时序。

每个新单组请求只播放 `MonitorSoundPattern` 对应的一组原声音：Info/Critical 一段，Notice 三段，Warning 为原有的双五联组。组内起点、音色及 PCM 素材保持不变。起点为当前渲染位置之后 480 frames，沿用 50 ms 启动过期期限。单组不会因组间 Period 到期自动循环；后续提醒必须使用新的正序号请求。

同一序号反复发布、组已结束后继续发布，以及取消后再次提交旧序号，都不会重播。单组播放期间，同级或更低等级的新请求合并到当前声音表现，不截断组，也不排队在结束后补播；高等级新请求可取消旧组并立即开始。单组完成边界按最后一个起点与原 PCM 样本长度计算，不能用触发确认时间、提醒间隔或声音组间隔代替。

null 取消当前已知 cue，正在渲染的音色沿用底层取消淡出；已进入设备队列的 PCM 不会被此接口撤回。Info 未开启 InfoTone、或零音量的新单组请求记为 SkippedSilent。连续模式的声音节奏及独立心搏声沿用原规则。

## 路由和优先级

```csharp
MonitorAlarmSoundRequest? Update(IReadOnlyList<AlarmLifecycleJournal> journals,
    int volumePercent, MonitorSoundTiming timing, bool enabled,
    IReadOnlyList<MonitorNotice>? notices = null);
```

属于 `AlarmNotificationSoundRouter`。一个实例绑定一组固定 journal owner，条件 ID 不可重复；启动后替换、删除或增加 owner，以及非法音量/时序，均在消费游标前拒绝。每次读取只消费游标之后的通知记录，并折叠到各条件的最新决定。只有事件身份、已确认等级和当次策略仍与当前条件一致的通知意图才有资格播放，恢复、禁用、中断或配置失效的旧意图不能复活。

只选择当前活动条件中的最高等级。相同等级同时到达的意图合成一个声音组，保留对应来源决策；低等级错过的意图不排队等高等级恢复。高等级仍活动而本次没有新提醒时，也不能由新低等级提醒取代它。正常恢复会取消属于已失效条件的声音请求；恢复后的重新发生仍受通知层的重复抑制。

### 混合提示来源

`notices` 是当前完整提示快照，省略或 null 表示没有外部提示；桌面实际刷新同时传递 `ActiveNotices`，不能仅根据横幅当前轮换项或最高等级重建来源。输入沿用提示集合的上限及字段约束，重复 ID、非法等级、空文本等在消费任何通知记录前拒绝。

已注册条件 ID 的横幅只作为显示，不作为未注册提示再次进入声音通道，即使其当前处于重复抑制、已恢复或不可判定。这避免同一个生理报警通过横幅绕过通知策略。其余信息、技术及显式测试提示保留原持续声音规则，不为它们虚构生理事件身份或重复抑制计时。

- 未注册提示中，`Audible=false` 不参与声音仲裁；Info 还须开启 `InfoTone` 才有资格出声。已注册条件的声音依据 journal 策略，不从横幅快照重建其启用状态。
- 未注册提示的最高可听等级高于或等于最高活动生理等级时，输出序号为零的持续请求。同级声音由持续来源承担，当前生理意图已消费，不作为待播队列保存。
- 生理等级更高时，由其通知策略决定是否发出单组；即使正处于重复抑制，也不改播较低级持续提示。
- 持续来源撤销后，不重播其遮蔽期间已消费的生理提醒；后续新提醒、升级或明确暂停后的恢复可产生新单组。较高生理条件解除后，仍存在的较低持续来源可继续播放。
- 相同等级、音量和时序的持续请求具有相等值，提示文本、排序或同级来源更换不重启声音组。切换持续/单组模式时按原排程器的替换、取消规则处理。

路由固定绑定 journal 集合，包括首次传入空集合的情况；不能在开始消费后补充 owner。需要不同注册范围时创建新的路由和播放 owner。

## 每个条件独立选择短／长警报

路由从当前条件策略的 `SoundDuration` 判断时长，不由严重程度或全局模式硬编码。SingleGroup 沿用一次声音组规则。Continuous 直接依据活动条件产生序号为零的持续请求；确认降级会调整其级别，不依赖可能仍记录旧等级的最后通知意图。恢复确认完成、禁用或不可判定后撤销来源。

相同等级中，只要还有有效长警报或未注册的持续提示，由持续请求承担声音；短警报意图被消费、不排队。更高级短警报可优先于低级长警报；高级条件解除后仍活动的低级长警报恢复。短改长可立即利用当前确认状态；长改短需新策略意图，旧意图不得复用。条件时长变更不重置生理事件身份或篡改横幅等级。

长警报的路由记录在 `ContinuousConditions` 中保留条件快照（含事件身份），区别于未注册提示的 `ContinuousNotices`。来源或请求未改变的刷新不追加记录，不重启声音组。长警报不表示锁存，也不等待尚未实现的用户确认。

## 暂停、恢复与音量

`enabled=false` 或零音量取消当前请求，但继续消费通知游标，不保存暂停期间的声音队列。重新启用时，仅依据仍然活动且没有处于重复抑制的当前事件产生一个新身份请求，避免重用已被排程器取消的身份。此判断也用于初次启用；已经恢复的事件不会因恢复播放而再次出声。

桌面将仿真暂停和操作性声音暂停共同映射到该入口。声音暂停仍使用现有交互时钟；计时结束不能自行启动已暂停的仿真。单组使用生成该请求时的音量和时序，非零音量修改在下一组生效；持续请求沿用原音量/时序更新规则。静音立即取消，解除静音重新判断当前条件及持续来源。重复刷新、倒计时刷新或再次绑定相同 journal 不新建组。

## 记录与可验证边界

- `Routes` 保存有界 `AlarmSoundRoutingRecord`：请求、对应决策快照，以及是否来自初次启用/恢复。正请求序号可与排程记录关联；持续请求序号为零，`ContinuousNotices` 保存未注册来源快照，`ContinuousConditions` 保存注册长警报条件快照，`Decisions` 为空。持续请求或其来源快照变化才追加记录，不给持续提示编造单组身份。`DroppedRouteCount` 报告路由历史淘汰。
- `MissedRecordCount` 累计通知源在消费前已被淘汰的记录数。迟到的消费者只对当前有效状态发出一个合并请求，不重播完整历史。
- `MonitorAlarmSequencer.Dispatches` 保存有界 `AlarmSoundDispatchRecord`，包含通知序号、阶段与渲染位置。阶段为 Selected、CoalescedWhileBusy、SkippedSilent、Interrupted、RenderWindowElapsed。
- `DroppedDispatchCount` 报告排程记录淘汰；`MissedNotificationCount` 从首个已见序号建立水位，累计之后跳过的请求序号，不补播单槽 mailbox 错过的请求。

上述缓冲区容量均为 `AlarmLifecycleJournal.Capacity`，返回只读快照。排程记录按处理顺序读取；旧组的结束记录可能位于较新请求的合并记录之后，不能仅按通知序号排序。各 owner 的计数互相独立，不代表全局身份或跨设备审计。

Selected 和 RenderWindowElapsed 只描述软件排程选择及渲染窗口，不证明设备交付成功、扬声器出声或用户已听见。物理设备故障、失败关闭、自动重连与实际交付确认仍沿用现有音频生命周期边界；本轮未新增设备确认、用户确认、保持或连续性恢复。

## 音频输出故障反馈

通知模式沿用 `SoundSettingsPanel.OutputNotice`：设备不可用、中断或释放失败显示 `audio-output`，其 `Audible=false`，不尝试通过失效设备播放自身故障，也不压低独立生理声音的优先级。发布请求、排程选择和渲染窗口结束均不能清除故障；取消重试也不证明恢复。成功试听完成或监护输出已有成功 pump 才沿用现有规则清除提示；释放失败继续禁止重开并要求重启客户端。

此边界是既有软件输出状态反馈，没有新增物理扬声器交付确认或自动重连。通知设置与保存映射见[通知策略接口](alarm-notification-policy.md)；用户确认与保持仍未实现。
